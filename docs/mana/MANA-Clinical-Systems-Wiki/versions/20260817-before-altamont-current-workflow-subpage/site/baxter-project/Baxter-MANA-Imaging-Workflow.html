1. The MRN problem is solvable without guessing

The current concern is:

MANA generates the final report using the MANA MRN, but Baxter needs the Baxter MRN to file the result in Oracle/Cerner.

I would not make demographics the primary cross-match.

Instead, carry both identifiers.

HL7 supports repeating patient identifiers with different assigning authorities, so conceptually PID-3 can contain:

MANA123456^^^MANA^MR
~
BAX789012^^^BAXTER^MR

The assigning authority is specifically how HL7 distinguishes identifiers issued by different systems or organizations. IHE's patient-identity profiles are built around exactly this problem: one person having identifiers in multiple patient-identity domains.

That immediately gives you a much better solution than:

“MANA MRN 12345 came back. Can Baxter figure out who that is?”

Instead Baxter receives:

“Here is the MANA identifier, and here is the Baxter identifier that you originally gave us.”

2. Even better: match the result to the original Baxter order

This is the part I would push hardest in the meeting.

The Baxter order number should survive the entire trip.

HL7 explicitly distinguishes:

Placer Order Number

The identifier assigned by the system that originally places the order.

Filler Order Number

The identifier assigned by the system that performs/fills the order.

HL7 uses ORC-2 / OBR-2 for the placer number and ORC-3 / OBR-3 for the filler number. The standard specifically emphasizes preserving these identifiers when results are returned in an ORU.

That is almost tailor-made for Baxter/MANA.
